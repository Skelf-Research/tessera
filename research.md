# Tessera — Research

Formal foundations, security proofs, and experiment harnesses behind the
Tessera protocol. This document indexes the research artefacts and summarises
the protocol's academic framing for citation and reproduction.

---

## Protocol summary

Tessera is an authenticated, metadata-private, one-to-one delivery protocol.

A sender proves identity to a recipient using a **Schnorr / Fiat–Shamir
zero-knowledge proof** under a per-recipient **blinded pseudonym**
`Y' = Y + tG` (`t = H(seed ‖ session_id) mod q`). The proof is AES-GCM
encrypted and routed over a **bucketed broadcast network** whose cover traffic
is calibrated to provide **(ε,δ)-differentially-private** sender↔recipient
metadata.

Three independent privacy mechanisms compose:

1. **Sender authentication without witness leak** — Schnorr / Fiat–Shamir in
   the ROM gives perfect honest-verifier zero-knowledge on the secret key `x`.
2. **Per-recipient pseudonyms** — `Y' = Y + t·G` is uniform per delivery to any
   party without the `shared_seed`; cross-recipient unlinkability.
3. **(ε,δ)-DP cover traffic** — load-independent shifted-Laplace noise on
   per-bucket counts.

No central authority; pairwise local enrolment.

## Security properties

| Property | Mechanism | Formal proof |
|---|---|---|
| Unforgeability | Schnorr binds (R, s, Y, m); EUF-CMA ⇐ DLog | Forking lemma |
| HVZK / NIZK | Fiat–Shamir transform in the ROM | Standard Schnorr ZK |
| Cross-recipient unlinkability | Per-recipient blinded pseudonym `Y'` | Blinding lemma |
| Replay resistance | Per-delivery commitment + receiver dedup | Freshness theorem |
| Metadata privacy | (ε,δ)-DP cover traffic, load-independent | Laplace mechanism |

### Threat model

| Adversary | Defence |
|---|---|
| Malicious sender (impersonation) | Unforgeability ⇐ DLog |
| Honest-but-curious recipient | Per-recipient blinding — `Y'` uniform across deliveries |
| Colluding recipients | Distinct `shared_seed`s → distinct `Y'` distributions |
| Global passive network observer | (ε,δ)-DP cover traffic |
| Replay attacker | Per-delivery commitment freshness + dedup |

Out of scope: compromised endpoint (secret key assumed intact on sender's
device; recipient runs verifier honestly).

## Protocol specification

### Notation

| Symbol | Meaning |
|---|---|
| `G`, `q` | SECP256k1 generator, group order |
| `H` | SHA-256 |
| `(x, Y)` | Sender long-term keypair (`Y = xG`) |
| `seed` | Per-contact `shared_seed` from enrolment |
| `session_id` | Per-delivery unique identifier |
| `t` | Blinding scalar `H(seed ‖ session_id) mod q` |
| `Y'` | Blinded pseudonym `Y + t·G` |
| `x'` | Blinded secret `x + t mod q` |
| `π` | Schnorr proof `(R, s)` on `(Y', m)` |
| `commit` | `H(Y' ‖ ephemeral_key ‖ session_id)` |
| `bucket` | `int(SHA256(commit)[:2]) mod 64` |
| `bloom_fingerprint` | `SHA256(commit ‖ window_start)[:8]` |

### End-to-end delivery (six steps)

1. **Enrol** (one-time, pairwise, out-of-band) — recipient stores sender's
   public key `Y` and a fresh `shared_seed`.
2. **Blind** — `t = H(seed ‖ session_id) mod q`, `Y' = Y + t·G`, `x' = x + t`.
3. **Commit** — `commit = H(Y' ‖ ephemeral ‖ session_id)`, registered to network.
4. **Encrypt** — `π = (R, s)` encrypted under routing key derived from `commit`;
   addressed to `bucket = H(commit) mod 64`.
5. **Route** — relays gossip the encrypted proof, adding calibrated DP cover
   traffic.
6. **Verify** — recipient matches by bloom fingerprint, decrypts, verifies `π`,
   and authenticates `Y' = Y + t·G` against `(Y, shared_seed, session_id)`.

### Schnorr / Fiat–Shamir proof

```
Prove(x, Y, m):
    r  ←$ Z_q
    R  = rG
    c  = H(R ‖ Y ‖ m) mod q
    s  = (r + c·x) mod q
    return π = (R, s)

Verify(Y, m, π):
    c  = H(R ‖ Y ‖ m) mod q
    accept iff  sG == R + cY
```

### (ε,δ)-DP cover traffic

```
D_b = max(0, round(μ + L)),    L ~ Laplace(0, 1/ε)
μ  ≥ (1/ε) · ln(1/(2δ))
```

The shifted-Laplace mechanism makes the published per-bucket count
`C_b = R_b + D_b` `(ε,δ)`-DP with respect to a single delivery event
(sensitivity 1). The truncation at 0 is the source of `δ`, bounded by `μ`.
Expected bandwidth cost ≈ `B·μ` dummies per round, independent of real load.

## Comparative leakage

| Scheme | Routing observer | Network eavesdropper | Recipient | Colluding recipients | Sender auth |
|---|---|---|---|---|---|
| Signed messaging (Signal-style) | 5 leaks | timing only | intended | none | yes |
| Metadata-private messaging (Vuvuzela/Stadium/Talek) | none | none | none | none | **missing** |
| **Tessera** | none | none | intended | none | **yes** |

Tessera has 0 unintended leaks and 0 authentication gaps.
